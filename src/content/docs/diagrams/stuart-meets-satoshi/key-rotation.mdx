Stuart rotates a key with each Beacon Type. In each sequence, Satoshi resolves the DID of Stuart and verifies the new
key. The aggregate sequences show the `n-of-n` signatures of the RECOMMENDED example and a `k-of-n` fallback. See
[n-of-n and k-of-n signatures](/diagrams/beacons/#n-of-n-and-k-of-n-signatures).

## Singleton Beacon

Stuart announces the update alone, with a Beacon Signal from a Beacon Address of Stuart.

## CAS Beacon

An Aggregation Cohort announces the update in a CAS Announcement. The cohort sees which DIDs have an update.

## SMT Beacon

An Aggregation Cohort announces the update in a Sparse Merkle Tree (SMT). The Aggregation Service sees only hashes.
