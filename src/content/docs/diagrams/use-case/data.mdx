## Data sources

Each color is one data source. Only the cohort gets data from the Aggregation Service. Satoshi gets the SMT Proofs
only from the Sidecar Data, because CAS never stores them.

## Data flow

Stuart rotates a key with an SMT Beacon. For each Beacon Signal, the leaf of Stuart in the SMT has one of three states:

- ✓ **inclusion:** the leaf is `hash(hash(nonce) + updateId)`. Satoshi applies the update.
- ○ **non-inclusion:** the leaf is `hash(hash(nonce))`. There is no update.
- ✗ **gibberish:** no SMT Proof of Stuart gives the SMT root. The DID is invalid (`INVALID_SIGNAL_DATA` or
  `MISSING_UPDATE_DATA`). With a `k-of-n` fallback, this can occur if Stuart did not sign.
